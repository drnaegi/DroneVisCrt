# 研究一 · 利用双源对应校准航拍相机的成对视角图文扩增

两张源照片中可重复定位的同一地物，为无人机记录的相对机位提供了一个校准尺度和方向的参照。本研究在近俯视、地表可近似为平面的条件下，利用这一约束校准机位，逐像素选择源照片取色，并将源像素的来源传递给描述核验。新视图生成仅使用源 RGB 和相机。图文配对另使用两幅源图的地物掩膜。目标实拍及其人工标注仅供评分。[实现](../../relation_nvs/aerial_mosaic.py) · [配对程序](../../tools/aerial_mosaic_pairs.py)

## 借用的部件与本研究的设计

| 来源 | 本研究采用的部分 | 如何使用 |
|---|---|---|
| Lowe 的 SIFT、RANSAC 稳健拟合 | 局部纹理对应和外点剔除 | 双向最近邻比值筛选，按棋盘网格分开拟合和检验，用截断像素误差选择遥测、相似变换或单应模型，保留可信的源间对应。[SIFT](https://doi.org/10.1023/B:VISI.0000029664.99615.94) |
| 平面诱导单应与多视图几何 | 同一地面点在各相机中的投影 | 把匹配点投到统一地平面，估计航迹水平位移的方向和尺度，用于两幅源图和每个目标机位。[Multiple View Geometry](https://www.robots.ox.ac.uk/~vgg/hzbook/) |
| IBRNet 等基于源观测的新视角绘制 | 多个源视角可共同提供目标像素外观 | 在具有源图覆盖的像素，按距源图边缘的余量和相机距离选择一张照片取色。每个像素同步纪录源编号，便于追查描述所依赖的像素。[IBRNet](https://arxiv.org/abs/2102.13090) |
| ViewCrafter | 成熟的点渲染条件视频扩散生成器 | 在相同源照片和同一组校正后的相机上，单独运行 sparse 权重、50 个采样步和固定种子 123，取轨迹第 8、16 帧作外部对照。[ViewCrafter](https://arxiv.org/abs/2409.02048) |

方法的可检验贡献，是用源间对应校正整段航迹的水平位移，然后让 RGB、地物标签和描述核验共享像素来源。独立实现可以拆掉校准、改变取色规则、检查来源图。匹配器、平面单应和源图重采样均有前人工作。

## 合成和描述

1. 将相机转换到东、北、天坐标系，地面为 z=0。FloodNet 的近天底 DJI 记录中出现横滚约 ±180° 的分支。当光轴离垂直向下不超过 2° 且记录的横滚绝对值大于 90° 时，将图像平面的两根轴同时翻转。此规则根据本次数据诊断得到，应用范围限于同类相机记录。若输入已经是经过验证的相机矩阵，省略原始 DJI 横滚字段。
2. 对第 i 个源间匹配，两个相机反投影到地面的差记作 eᵢ，以中位数估计系统性偏移 e。源相机水平位移为 b，将平面向量写成复数后，用 (b+e)/b 拟合旋转和比例，以第一源为原点校准其它相机的水平位置。匹配数至少 12、源间距超过 1 米、地面偏移的中位残差小于源间距的 10%、比例介于 0.5 和 2 时才启用，否则沿用遥测。
3. 将目标像素通过地平面反投影到两张源图。在画内的源中，选择“至边缘的距离（封顶 16 像素）除以 16，减去归一化机位距离”最大者取色。两图都没有覆盖时按源图边界镜像补纹理，并将来源标为 0。该规则判断投影覆盖，深度遮挡和非平面物体仍可能产生错位。
4. 两张源图各自枚举从道路内部、穿过草带、到达水面的候选截线。检查中线和两条平行偏移线，在两个目标视角的源标签投影上同时核验地物顺序，选画内余量最大的一对。来源为 0 的区域一律记未知。每地点最多输出一对，弃选计入分母。最终在相同位置独立读取两幅目标实拍的标注。人工对生成 RGB 的独立读图尚待完成。

## 效果与对照

每个地点先对目标视角求平均，再对地点等权。LPIPS-Alex 衡量感知差异，RGB MAE 按 0–1 归一化。两者越小越好。Road/Water IoU 衡量投影标签与目标标注的一致性，其中道路合并淹水和未淹水道路，水为独立水面类别。IoU 只评价二维标注传递。数据来自同一个 FloodNet 灾后航拍集合。[FloodNet](https://github.com/BinaLab/FloodNet-Supervised_v1.0)

| 方法 | 诊断组 16 地 LPIPS | 诊断组 MAE | 确认组 3 地 LPIPS | 确认组 MAE |
|---|---:|---:|---:|---:|
| 统一横滚约定，双源平均 | 0.4435 | 0.1084 | 0.3382 | 0.0803 |
| 统一横滚约定，逐像素选源 | 0.4127 | 0.1073 | 0.2877 | 0.0781 |
| 再加双源位移校准，双源平均 | 0.4053 | 0.1009 | 0.2948 | 0.0685 |
| 再加双源位移校准，逐像素选源（完整方法） | **0.3754** | **0.1002** | **0.2479** | **0.0669** |

最早 5 个地点用于渲染方案开发。随后 16 个地点、32 张目标图按机位选择，与开发机位至少间隔 230 米。在这 16 地上，未经横滚和位移校准的两图平均与逐像素选源 LPIPS 为 0.5860、0.5777，使用源间匹配直接局部形变则为 0.5829。这些结果用于排查姿态问题，因此 16 地属于修订方法的诊断数据。校准同时改善标签传递，诊断组道路与水面 IoU 由 0.3985 升至 0.4324。源投影覆盖率为 60.9%，其余为补边。[初版逐图结果](fresh/scores.json) · [修订版逐图结果](calibrated/fresh/scores.json)

冻结修订方法后，以相机中心 110 米间隔排除已用地点，要求第一源标注能构成至少一条指定地物截线。遍历所得 3 个新地点共有 6 张目标图，实际与旧机位最小距离为 115–138 米。该距离限制作用于相机中心，地面视野可能重叠。相同校准下，完整方法相对双源平均在三个地点的 LPIPS 降幅依次为 0.0826、0.0461、0.0121。平均投影覆盖率为 80.2%，道路与水面 IoU 为 0.6394。该组经过源侧语义筛选，样本量小，只能评价此类场景。[冻结清单](confirmation/sites.json) · [确认组逐地点与逐图结果](calibrated/confirmation/scores.json)

诊断组按预定顺序取前四地，在相同校准机位上实际重跑 ViewCrafter。完整方法与 ViewCrafter 的 LPIPS 分别为 0.3630 和 0.5346，MAE 为 0.0829 和 0.0863。目标图均按 512×384 评价，ViewCrafter 按工作区既有的 25 帧宽屏生成和缩放流程运行。该结果限定于此次基线适配及近俯视相机。[外部基线逐图分数](vc_calibrated_first4/comparison.json)

在确认组全部 3 个地点上，用同一组校正机位重跑 ViewCrafter，LPIPS 为 0.3319，MAE 为 0.0689，完整方法分别为 0.2479、0.0669。[确认组外部基线逐图分数](vc_confirmation/comparison.json)

确认组按全幅实拍 RGB 补算 PSNR 和 SSIM，逐图评分后按地点等权。完整方法为 19.3243 dB、0.4767，同相机双源平均为 19.2118 dB、0.4740，ViewCrafter 为 19.1721 dB、0.4772。本次全幅计算包含动态区域和补边区域；开题报告第 41 页的合成场景协议另要求在静态有效区域评分。[逐图 PSNR、SSIM 与实现参数](calibrated/confirmation/full_frame_psnr_ssim.json)

## 复跑与产物

在仓库根目录运行下列命令生成一对新图。JSON 中每个相机包含编号、内参、东-北-天坐标系中的 OpenCV camera-to-world 矩阵及分辨率。两幅源 RGB 的文件路径相对于清单；目标条目只需相机参数。每个目标目录含 RGB 和像素来源图（0 为镜像补边，1 和 2 为源编号）。代码会拒绝地平线穿过图像的相机。[输入示例](example_input.json) · [已运行的双视角输出](calibrated/example_pair/manifest.json)

```bash
PYTHONPATH=. python -m tools.render_aerial_mosaic outputs/aerial_mosaic_validation/example_input.json /tmp/aerial_mosaic_example
```

已有缓存上的评测入口为 `tools/calibrate_aerial_mosaic.py generate` 和 `score`，确认组加 `--confirm`。LPIPS 评分使用工作区含 lpips 的环境。描述选择和核验依次为 `tools/aerial_mosaic_pairs.py select --calibrated` 和 `audit --calibrated`。每一组外部基线依据其 status.json 检查相机及生成图哈希，再由 `tools/score_aerial_mosaic_controls.py` 评分。[测试记录](tests.log)
