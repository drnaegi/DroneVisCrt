# 方法选择与复现说明

日期：2026-10-23。此轮目标是回应近视角试跑不足的问题，构建具有明显观察方向变化、同时包含新显露区域补全的实验。

## 为什么选择 ViewCrafter

| 方法 | 本次核查到的能力与条件 | 本轮状态 |
|---|---|---|
| ViewCrafter，TPAMI 2025 | 单图/稀疏图几何条件视频扩散，公开轨迹控制，支持横向与俯仰变化；正好对应原报告的基础路线 | 已安装并执行，结果见同目录实验报告 |
| WAVE，ICCV 2025 | 使用 MegaScenes 的 warp + pose 模型进行新视角生成，关注视角一致性；公开代码和检查点获取命令 | 已核查官方 README，未在本轮运行 |
| ZeroNVS | 单图场景新视角与 360° 场景重建路线；官方端到端评估涉及每场景约 3 小时 NeRF 蒸馏，输入为 256×256 | 已核查官方 README，未在本轮运行 |

来源：[ViewCrafter](https://github.com/Drexubery/ViewCrafter)、[论文](https://arxiv.org/abs/2409.02048)、[WAVE](https://github.com/jwoo-park0/WAVE)、[ZeroNVS](https://github.com/kylesargent/ZeroNVS)。其他方法的速度和显存不能由本轮 ViewCrafter 实测推断。

本轮采用官方 **ViewCrafter_16** 权重，16 帧、1024×576。官方将其标为消融用版本；不是 25 帧主版本。选择它是为了在 RTX 4090 24GB 上保留较高图像分辨率，并为当前 PyTorch 版本预留显存。不能把结果写成对论文最强配置的完整复现。

## 实现适配

入口：`tools/run_viewcrafter_trial.py`。官方源代码保持下载时内容，适配放在本地包装层。

1. DUSt3R 从官方 safetensors 加载；将 safetensors 去重后的 8 个共享层别名恢复为同一权重引用，再执行严格加载，未随机补齐参数。
2. ViewCrafter 初始化 OpenCLIP 时跳过单独下载预训练权重；随后从完整 ViewCrafter 检查点严格加载所有组件，包括文本和图像编码器。
3. 将交叉注意力和 VAE 注意力计算换成 PyTorch SDPA，保持原来的查询/键/值、缩放、图像与文本分支组合；不安装与当前 PyTorch 不匹配的旧 xformers。
4. 在随机小张量上对照原实现，三种自注意力/交叉注意力配置与 VAE 注意力的 FP32 最大绝对差均小于 `3e-7`。这验证了这些算子的数值对应，不能推导整条生成结果与官方旧环境逐像素相同。
5. 开启官方 `perframe_ae=True`；几何阶段与扩散阶段分别运行，释放 DUSt3R 后加载扩散模型。
6. 用 Pillow 的 `Resampling.LANCZOS` 对应旧代码的 `Image.ANTIALIAS`。输出视频使用 imageio 编码。

DUSt3R 在单图模式下按官方流程复制输入组成一对图，并执行几何优化；这不是检测器或生成模型的训练。16 帧扩散采用官方 DDIM 实现、50 步、eta=1、CFG=7.5、guidance rescale=0.7、seed=123，提示词为官方默认 `Rotating view of a scene`。

## 本机复现

以下命令依赖本机已经准备好的源代码、环境、权重和前轮公开航拍输入：

```bash
cd /root/DroneVisCrt
bash tools/reproduce_wide_view_trials.sh all outputs/wide_view_trials_rerun
envs/viewcrafter/bin/python tools/summarize_wide_view_trials.py \
  --root outputs/wide_view_trials_rerun
```

分阶段运行时，先执行 `geometry`，再执行 `generate`，使用同一输出目录。第二阶段会检查场景与轨迹参数是否与缓存一致。

每个实验目录保存 `input.png`、`conditions/`、`generated/`、两段原始视频、相机参数 `cameras.json`、模型配置、运行记录 `run.json`、原始几何与条件数组。汇总脚本生成关键帧、三列对比视频和原图/终点切换 GIF。

`conditions` 是几何投影条件，黑洞表示未被点云覆盖；`generated` 是实际扩散输出。汇总材料不对生成图做修复，也不把原图替换到生成视频中冒充保真结果。
